# medical-writing-style

面向中文医药写作与审核的 GitHub Copilot Skill。

这个 skill 适用于肿瘤报告、证据锚定幻灯、临床开发进展、监管沟通、指南摘要、获益风险评估和科学改写等场景。目标不是把文本写得更花，而是把表达收紧到“证据为中心、边界清楚、语言自然、不过度营销”的状态。

## 这个 skill 做什么

- 改写中文医药文本，使表述更直接、具体、可执行
- 保留原始事实、数字、终点、人群、日期、引用和不确定性
- 避免把探索性、描述性、单臂或跨试验结果写成确定性结论
- 保留 FDA、NMPA/CDE、NCCN、CSCO 等受控术语和监管/指南语境
- 去掉常见 AI 套话、主持腔、抽象管理黑话和空泛收尾

## 适用范围

适用于以中文为主体的文本，包括中文中正常嵌入的：

- 英文药名、研究名
- 终点与统计缩写，如 OS、PFS、HR、95% CI
- 英文骨架模板，如 Executive Communication、Evidence-Anchor

不适用于：

- 以英文为主体的整篇文本
- 需要核实底层临床事实真伪的任务
- 生成新的医学证据、医学建议或监管结论

## 典型使用场景

- 学术会议或内部汇报文案润色
- 证据锚定页标题与正文收紧
- 监管沟通纪要、问答材料、审评讨论支持文案
- 指南摘要、竞品证据格局梳理
- 研究中心邮件或内部医学评审意见改写

## 核心原则

这个 skill 的判断顺序是：

1. 先保真：事实、数字、终点、人群、日期、引用、不确定性不能被风格化破坏。
2. 再守边界：监管、指南和统计术语不能被“更顺口”的说法替换。
3. 最后自然化：只在不改变证据强度的前提下，去掉套话并压缩表达。

默认输出风格是：

- 结论先行
- 直接、具体
- 克制而非口号式
- 自然但不随意
- 写清主体、动作、条件和下一步

## 安装方式

将本仓库放到 GitHub Copilot 的用户级 skills 目录下，目录名建议保持为 `medical-writing-style`。

### Windows

将仓库放到：

```text
%USERPROFILE%/.copilot/skills/medical-writing-style
```

### macOS / Linux

将仓库放到：

```text
~/.copilot/skills/medical-writing-style
```

放置完成后，重启 VS Code 或重新加载 Copilot 会话。

## 使用方式

在支持 skills 的 Copilot 环境中，可直接给出待处理文本，并明确任务目标，例如：

```text
用 medical-writing-style 帮我改这段 NSCLC 项目汇报，保留所有数据和限定语，只收紧语言。
```

```text
按 medical-writing-style 审核这页证据锚定 slide 标题，避免把探索性结果写成确定性结论。
```

```text
用 medical-writing-style 改写这封研究中心邮件，保留医学判断边界，语气更直接。
```

如果改动触及以下内容，建议让模型同步给出简要变更说明：

- 数字
- 终点
- 分析人群
- 日期
- 引用
- 限定语
- 监管或指南固定术语

## 设计边界

这个 skill 只处理语言层，不替代以下工作：

- 文献核查
- 数据源核对
- 统计复核
- 监管结论确认

如果原始材料本身存在事实错误、数据过期或来源不明，这个 skill 只能帮助把风险表述清楚，不能把问题“润掉”。

## 输出预期

理想输出应满足以下几点：

- 读起来像真实业务作者写的，而不是模板化 AI 文案
- 证据强度不被抬高
- 局限性和不确定性仍然可见
- 对医学、监管和管理层语境都可直接使用或少量修改后使用
